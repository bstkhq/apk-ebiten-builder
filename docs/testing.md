# Testing and CI

This guide is for contributors and maintainers of `apk-ebiten-builder`. It is
not required to build an APK from a consuming project.

## Host prerequisites

The normal build prerequisites in the root README are sufficient for Android
builds. On Debian or Ubuntu, the host-side Go test gate also needs Ebiten's
native development packages:

```bash
sudo apt-get install libc6-dev libasound2-dev libgl1-mesa-dev libx11-dev \
  libxcursor-dev libxi-dev libxinerama-dev libxrandr-dev libxxf86vm-dev pkg-config
```

## Local gates

| Command | Covers |
| --- | --- |
| `make test` | Java and Go contracts, bootstrap, dependency and template checks, plus device-helper tests. |
| `make test-android` | `make test`, every fixture APK, Android lint, signatures and 16 KiB alignment checks. |
| `make test-device` | `make test-android` plus runtime checks on a connected Android device. |

The Android build gate compiles the legacy fixture, the `bridge` runtime
fixture, and independent Back, file-picker and IME fixtures. It inspects the
actual Java signatures generated by gomobile, runs Debug and Release lint,
verifies APK signatures, and checks ZIP and native ELF alignment. It defaults
to amd64 plus arm64; set `ANDROID_TARGET` when a narrower fixture is required.

The builder supplies the NDK r26 linker flags required for 16 KiB-aligned
native libraries, independently of values injected through `GO_LDFLAGS`.

## Continuous integration

GitHub Actions runs `make test-android` for every pull request and every push
to `main`. It installs Android tooling through `Dependencies.mk`, pins
`ebitenmobile` to the fixture's Ebitengine version, and caches the SDK based
on that installer configuration.

The device gate remains manual because it needs a connected Android device.

## Device gate

Set `ADB_SERIAL=<serial>` to select a device and
`DEVICE_TIMEOUT_SECONDS=<seconds>` to adjust its overall timeout. The scripts
install only the private fixture packages under `games.example.builder.*` and
force-stop them on exit.

Before changing the device, the shared harness records its `GoLog` level and
keep-awake setting. It wakes and unlocks the display, waits for a stable
top-resumed Activity, and restores those settings even if a test fails. The
helper itself is tested with a fake ADB transport, including an unset-setting
case.

The device checks cover runtime services and restart, consumed and delegated
Back events, picker selection and cancellation, and IME show, text input and
Go-requested hide.
